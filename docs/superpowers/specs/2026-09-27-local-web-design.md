# 本地员工手册问答：技术选型与设计

用户已认可三栏设计稿、添加JD logo，明确先本地跑通、部署另议；2026-09-27要求保存讨论并开始实施。

## 技术选型
HTML/CSS/JavaScript + FastAPI/Uvicorn，同源Fetch/JSON，无Node构建。历史仅存浏览器localStorage，提供清除记录。模型密钥留在服务端.env。复用Python检索/生成与缓存，不重写Java服务。Java适合已有企业业务平台集成，必要时可以调用Python AI服务；本项目无相关需求，不增加双服务运维成本。未测Python/Java性能对照，不声称语言带来速度提升。

## 页面与交互
左侧示例及历史，中间问答/输入/三种方案/仅检索，右侧证据页码章节正文。JD logo直接使用用户原图，不使用生成图片作为产品界面。窄屏证据在回答下方。引用按钮定位对应原文；原方案页码路径引用采用原有标记，优化方案编号映射实际输入块。回答使用安全文本呈现，不执行模型HTML。

## 接口及运行
GET /api/health返回服务/API配置是否就绪，不返回密钥。POST /api/ask接受question(1..500字符)、profile(baseline/quality/fast)、retrieval_only。质量模式guarded+evidence+low，快速guarded+evidence+disabled。返回回答、实际证据映射、分阶段耗时、每次尝试用量、完整状态与可操作错误。请求级usage_sink隔离用量。检索缓存首次加载受锁保护；本地演示串行处理RAG请求，繁忙时明确提示，不把无限排队包装成低延迟。API异常不返回原始异常文本，保留证据，提示操作；截断明确标记。

默认绑定127.0.0.1:8000，无公开部署、账号系统和上传文档。先完整回答再显示，不伪装流式生成。

## 验收
接口测试：输入校验、仅检索无需模型、来源对应实际输入、失败保留证据/不泄露异常、截断、用量隔离与busy。浏览器核对桌面及窄屏、引用联动、历史、新建、清除和错误。真实本地检索及至少一次模型调用，记录实测而非使用历史评测数字。每个验证单元本地commit；完整批次推送。
