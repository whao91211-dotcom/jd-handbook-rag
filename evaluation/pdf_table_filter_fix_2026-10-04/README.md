# PDF 表格区域过滤遗漏修复

## 原因与改动

第 48 页普通列表被 pdfplumber 判为两个单列表格。第一个检测区域覆盖了网址的一部分，但单元格只提取了“访问地址”等标签。旧逻辑直接删除整个检测区域，既没有正文，也没有表格收录 `ssc.jd.com`。

修复先按同样的区域边界提取原文，比较区域原文与表格单元格的非空白字符计数。只有单元格保留了全部字符，才移除区域正文并输出表格；否则保留原文，放弃该区域的结构化表格表示，避免重复。字符计数用于防止遗漏，不证明阅读顺序或表格关系正确。表格处理异常时回退整页文本。`preserve_unrepresented_text=False` 保留旧策略用于消融。

实际逐页比较中只有第 48 页发生变化。结构化表格对象从 8 个变为 6 个，分块从 125 个变为 123 个；其余 50 页的逐页记录完全相同。医疗期等真实表格保持结构化表示。

## 同批测量

完整重跑原 PDF。相同清洗、条款分块、BGE、Chroma、BM25、RRF 与 guarded 策略；仅对照表格过滤逻辑。未调用回答模型或 OCR。

| 指标 | 旧策略 | 修复后 | 变化 |
|---|---:|---:|---:|
| 11 页抽查的原文检查点 | 60/65 | 65/65 | +5 |
| 所有检查点顺序正确的页面 | 6/11 | 7/11 | +1 |
| 相邻检查点顺序正确 | 45/54 | 50/54 | +5 |
| 选定表格行文本对应 | 10/10 | 10/10 | 不变 |
| 10 个用例的原文证据可用率 | 9/10 | 10/10 | +10 个百分点 |
| 10 个用例的 Top-8 完整证据覆盖 | 8/10 | 9/10 | +10 个百分点 |
| 相同 6000 字符预算证据覆盖 | 9/10 | 10/10 | +10 个百分点 |

恢复的是 pdf09 网址用例。pdf06 调动问题仍需更多候选，Top-8 未覆盖完整证据，6000 字符预算模式可覆盖。修复没有解决其他页面的表格阅读顺序问题。

原始检索集的回归单独记录在 `gold_regression.json`：34 个引用 ID 未变化的正例，旧/新均 34/34 完整覆盖；既有 26 个唯一原文引句用例均 26/26；第 48 页 P32 的旧 ID 随内容变化失效，因此单独按原来的原文引句核对，旧/新均通过。不把旧 ID 失效当作检索质量下降，不重新编造 gold 标签。

这是开发/回归数据，不是独立真实用户测试，也没有测量回答正确率、API 成本收益。解析和检索耗时见 `summary.json`，单次运行不支持稳定性能增益结论。
